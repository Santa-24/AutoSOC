1. WHAT IS THE USE OF THIS PROJECT?
--------------------------------------------------------------------------------
AutoSOC is an AI-assisted, autonomous Cloud Security Operations Center (SecOps) 
platform designed specifically for Amazon Web Services (AWS).

In modern cloud infrastructures, security operations teams face "Alert Fatigue": 
hundreds of thousands of raw events stream continuously across multiple isolated 
AWS tools (AWS CloudTrail, Amazon GuardDuty, AWS Security Hub, Amazon Inspector, 
and AWS Config).

AutoSOC solves this problem by:
  - Continuously aggregating telemetry across compute (EC2), storage (S3), 
    and identity (IAM).
  - Correlating seemingly unrelated security anomalies into unified, contextual 
    incident graphs (e.g., matching an unusual EC2 outbound connection with a 
    subsequent IAM policy modification and an S3 bucket permission change).
  - Utilizing Amazon Bedrock AI models (Claude 3 Sonnet) to synthesize attack 
    timelines, evaluate blast radius, and explain root causes in plain language.
  - Providing automated, pre-packaged remediation playbooks with dry-run 
    simulation safeguards and mandatory human-in-the-loop approval gates.
  - Recording all actions into a cryptographically tamper-evident, append-only 
    audit log with SHA-256 integrity digests.


2. THE 7-STAGE SEC-OPS LIFECYCLE
--------------------------------------------------------------------------------
AutoSOC automates the end-to-end incident response pipeline through 7 stages:

  [01] DETECT:
       Real-time event streaming from AWS Security Hub, Amazon GuardDuty, 
       AWS CloudTrail, and Amazon Inspector across multi-region accounts.

  [02] CORRELATE:
       Discovers attack paths by correlating ephemeral VPC compute anomalies 
       with IAM credential abuse and S3 storage policy modifications.

  [03] TRIAGE:
       Deterministically prioritizes incidents by evaluating real blast radius, 
       asset sensitivity tags (e.g., PCI-DSS, PII), and MITRE ATT&CK techniques.

  [04] INVESTIGATE:
       Synthesizes incident evidence using Amazon Bedrock with strict prompt 
       injection defense and evidence citations. Never modifies resources without 
       oversight.

  [05] APPROVE / RESPOND:
       Executes precision remediation playbooks (EC2 isolation, IAM key revocation, 
       S3 bucket public access blocks). Destructive operations always simulate a 
       dry-run preview first and require authorized analyst confirmation.

  [06] RECORD:
       Logs every action, actor, timestamp, and AWS request ID into an append-only 
       audit log backed by SHA-256 chain-of-custody verification.

  [07] REPORT:
       Maps findings against regulatory frameworks: CIS AWS Foundations Benchmark, 
       NIST CSF 2.0, ISO 27001, and SOC 2 Type II.


3. HOW DIFFERENT USERS WILL USE THIS PLATFORM
--------------------------------------------------------------------------------
AutoSOC is built to serve multiple cross-functional stakeholders:

A. TIER 1 SOC ANALYSTS (TRIAGE & MONITORING):
   - Workflow:
     1. Monitor the SecOps Command Center (Dashboard) for elevated risk scores.
     2. Review the aggregated Security Findings feed.
     3. Identify active attack paths rather than sifting through thousands of 
        individual raw log events.
   - Key Screens:
     * Dashboard (/dashboard)
     * Security Findings (/incidents)

B. TIER 2 & TIER 3 INCIDENT RESPONDERS (DEEP INVESTIGATION):
   - Workflow:
     1. Drill into specific incident workspaces to review AI-generated attack 
        summaries and affected asset graphs.
     2. Inspect raw CloudTrail event logs via the Forensic Timeline, verifying 
        tamper-evident SHA-256 hashes for chain of custody.
     3. Log investigative findings and IP whois notes directly onto incident 
        records.
   - Key Screens:
     * Incident Detail & Blast Radius (/incidents/[id])
     * Forensic Timeline & Chain of Custody (/forensics)
     * AI Investigation Workbench (/investigations)

C. SECOPS LEADS & CLOUD SECURITY ARCHITECTS (RESPONSE & REMEDIATION):
   - Workflow:
     1. Review proposed response playbooks for containment.
     2. Click "Generate Dry-Run Blast Radius Preview" to simulate the exact AWS CLI 
        mutation and verify potential outage risk.
     3. Complete the two-step authorization gate to quarantine compromised EC2 
        instances, revoke compromised IAM access keys, or enforce S3 bucket 
        access blocks.
   - Key Screens:
     * Response Playbook Catalog (/response-playbooks)
     * Incident Response Workbench (/incidents/[id])

D. CLOUD DEVOPS & SRE TEAMS (INFRASTRUCTURE & INTEGRATIONS):
   - Workflow:
     1. Monitor real-time connectivity of AWS services (Security Hub, GuardDuty, 
        CloudTrail, KMS, S3, DynamoDB).
     2. Identify missing IAM permissions or configuration drift.
     3. Ensure production environments are defended without risking unexpected 
        workload downtime.
   - Key Screens:
     * AWS Integrations Health (/integrations)
     * Preferences & Settings (/settings)

E. COMPLIANCE OFFICERS & AUDITORS (GOVERNANCE & GRC):
   - Workflow:
     1. Review the append-only SecOps audit log.
     2. Validate that all administrative actions have verified actor signatures, 
        timestamps, and AWS request IDs.
     3. Export evidence to support SOC 2, ISO 27001, and CIS benchmark audits.
   - Key Screens:
     * SecOps Audit Log (/audit-log)
     * Documentation (/docs)


4. WHY IS AUTOSOC USEFUL? (KEY BUSINESS & TECHNICAL VALUE)
--------------------------------------------------------------------------------
1. REDUCTION IN MTTR (MEAN TIME TO RESPOND):
   Reduces average incident triage and response from hours/days down to seconds. 
   Pre-built response playbooks eliminate the need to write custom CLI scripts 
   during an active attack.

2. ACCIDENTAL OUTAGE PREVENTION (DRY-RUN SAFEGUARDS):
   Automated security tools often terrify infrastructure teams because a bug might 
   accidentally take down a production database or customer-facing API. AutoSOC 
   enforces non-negotiable dry-run simulations: you see the exact affected ENIs, 
   instances, and outage risk before anything is modified.

3. ZERO BROWSER SECRETS:
   Frontend web clients never receive AWS credentials, session tokens, or KMS 
   keys. All communication with AWS APIs occurs server-side via authenticated 
   Next.js route handlers.

4. CRYPTOGRAPHIC PROOF OF CUSTODY:
   Every forensic log captured from AWS CloudTrail is stamped with a SHA-256 
   digest and verifiable custody attestations, ensuring evidence cannot be 
   tampered with.

5. COST-EFFECTIVE ARCHITECTURE:
   Uses serverless on-demand AWS building blocks (DynamoDB Pay-Per-Request, 
   S3 Glacier-ready audit storage, free management CloudTrail events) incurring 
   near $0.00 base operating overhead.
