================================================================================
AUTOSOC — AWS CREDENTIALS & SERVICE SETUP GUIDE (FROM SCRATCH)
================================================================================
Target Audience: Security Engineers, DevOps Analysts, and Cloud Beginners
Operating Region: ap-south-1 (Mumbai) or your chosen AWS region

IMPORTANT SAFETY NOTICE:
1. NEVER use the AWS root user access keys for local development.
2. AutoSOC runs out-of-the-box in DEMO MODE ($0.00 cost) without any AWS keys.
3. Only follow these steps when you are ready to connect to a live AWS account.

--------------------------------------------------------------------------------
PART 1: BEGINNER-FRIENDLY AWS CONSOLE SETUP (STEP-BY-STEP)
--------------------------------------------------------------------------------

STEP 1: Log in to AWS Management Console
1. Navigate to https://aws.amazon.com/console/
2. Log in using an IAM Administrator or IAM Identity Center user (NOT root).
3. Ensure your region selector in the top-right corner matches your intended
   region (e.g., "Asia Pacific (Mumbai) ap-south-1").

STEP 2: Create a Scoped IAM User for Local AutoSOC Development
1. Open the IAM Console: https://console.aws.amazon.com/iam/
2. In the left navigation, click "Users" -> "Create user".
3. User name: `autosoc-dev-operator`
4. Leave "Provide user access to the AWS Management Console" UNCHECKED (API only).
5. Click "Next".
6. In "Permissions options", choose "Attach policies directly".
7. Click "Create policy" (opens new tab), switch to the "JSON" tab, and paste:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AutoSOCReadTelemetry",
      "Effect": "Allow",
      "Action": [
        "sts:GetCallerIdentity",
        "securityhub:DescribeHub",
        "securityhub:GetFindings",
        "guardduty:ListDetectors",
        "guardduty:GetDetector",
        "guardduty:ListFindings",
        "guardduty:GetFindings",
        "cloudtrail:DescribeTrails",
        "cloudtrail:LookupEvents",
        "config:DescribeComplianceByConfigRule",
        "inspector2:ListCoverage",
        "inspector2:ListFindings"
      ],
      "Resource": "*"
    },
    {
      "Sid": "AutoSOCRemediationDryRunAndGatedExecution",
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:ModifyInstanceAttribute",
        "iam:UpdateAccessKey",
        "s3:PutBucketPublicAccessBlock",
        "s3:GetBucketPublicAccessBlock",
        "wafv2:UpdateIPSet",
        "wafv2:GetIPSet"
      ],
      "Resource": "*"
    }
  ]
}

8. Name policy: `AutoSOC-Operator-Policy` and click "Create policy".
9. Return to the user creation tab, refresh policies, select `AutoSOC-Operator-Policy`.
10. Click "Next" -> "Create user".

STEP 3: Generate Local Development Access Keys (Fallback Method)
1. In the IAM Users list, click `autosoc-dev-operator`.
2. Click the "Security credentials" tab.
3. Scroll to "Access keys" and click "Create access key".
4. Select use case: "Command Line Interface (CLI)" or "Local code".
5. Check the confirmation acknowledgment and click "Next".
6. Copy the "Access key ID" and "Secret access key" immediately.
   (Store securely in your password manager; you cannot view it again).

--------------------------------------------------------------------------------
PART 2: PREFERRED ENTERPRISE SETUP (AWS CLI PROFILE / IDENTITY CENTER)
--------------------------------------------------------------------------------

Instead of static access keys, AWS recommends AWS IAM Identity Center (SSO):

1. Install AWS CLI v2:
   https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html

2. Run SSO Configuration:
   $ aws configure sso
   SSO session name: autosoc-sso
   SSO start URL: https://<your-org>.awsapps.com/start
   SSO region: ap-south-1
   SSO registration scopes: sso:account:access

3. The CLI will open a browser login window. Authorize the session.
4. Set the profile name in your shell:
   $ export AWS_PROFILE=default

AutoSOC automatically detects this profile through `@aws-sdk/credential-providers`!

--------------------------------------------------------------------------------
PART 3: ENABLING AWS SECURITY SERVICES (FREE TRIALS & COSTS)
--------------------------------------------------------------------------------

1. AWS Security Hub:
   - Go to https://console.aws.amazon.com/securityhub/
   - Click "Go to Security Hub" -> "Enable Security Hub".
   - Cost: 30-day free trial in new accounts; ~$0.0010 per finding check after.

2. Amazon GuardDuty:
   - Go to https://console.aws.amazon.com/guardduty/
   - Click "Get Started" -> "Enable GuardDuty".
   - Cost: 30-day free trial; billed on CloudTrail and VPC Flow Log volume.

3. AWS CloudTrail:
   - Go to https://console.aws.amazon.com/cloudtrail/
   - First multi-region trail of management events is FREE.
   - Event lookup within the past 90 days requires no additional setup.

4. Amazon Bedrock (Optional for AI Investigations):
   - Go to https://console.aws.amazon.com/bedrock/
   - Click "Model access" in left navigation.
   - Click "Manage model access" -> request access for "Anthropic Claude 3 Sonnet".
   - Approval is typically instantaneous or within a few minutes.
   - Cost: Pay-as-you-go per token (~$0.003 / 1k input tokens).

--------------------------------------------------------------------------------
PART 4: VERIFICATION & HEALTH CHECKS
--------------------------------------------------------------------------------

1. Test credentials in your terminal:
   $ aws sts get-caller-identity
   # Expected Output:
   # {
   #   "UserId": "AIDAI...",
   #   "Account": "123456789012",
   #   "Arn": "arn:aws:iam::123456789012:user/autosoc-dev-operator"
   # }

2. Launch AutoSOC locally:
   $ npm run dev

3. Open your browser:
   http://localhost:3000/integrations

4. Click "RE-VERIFY SERVER-SIDE INTEGRATIONS".
   AutoSOC will execute real STS and service health calls.
   When connected, the green "CONNECTED" status badge will illuminate.

--------------------------------------------------------------------------------
PART 5: TROUBLESHOOTING COMMON ERRORS
--------------------------------------------------------------------------------

Error: "CredentialsProviderError: Could not load credentials from any providers"
Fix: Run `aws configure` or set `AWS_PROFILE=default` in your environment.
     Ensure your local `.env.local` contains `AWS_REGION=ap-south-1`.

Error: "AccessDeniedException: User is not authorized to perform: securityhub:GetFindings"
Fix: Check that `AutoSOC-Operator-Policy` is attached to your user or role.
     Verify that Security Hub has been enabled in the target region.

Error: "AccessDeniedException: Your account is not authorized to invoke Bedrock"
Fix: AutoSOC automatically activates its Deterministic Rule Engine fallback!
     To enable Claude 3, visit AWS Bedrock Console -> Model Access -> Request access.

--------------------------------------------------------------------------------
PART 6: TEARDOWN & CLEANUP (AVOIDING UNINTENDED CHARGES)
--------------------------------------------------------------------------------

When you have finished testing AutoSOC:
1. Delete the IAM Access Key in AWS IAM Console -> Users -> Security credentials.
2. If using Terraform:
   $ cd terraform
   $ terraform destroy
3. If you enabled GuardDuty or Security Hub for testing only, you can disable them
   via their respective console "Settings" -> "Disable" to halt background checks.
