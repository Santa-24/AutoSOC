1. EXECUTIVE PROJECT SUMMARY & CORE PURPOSE (PROJECT USE)
================================================================================

WHAT IS AUTOSOC?
AutoSOC is a production-grade, AI-powered Autonomous Security Operations Center 
(SOC) specifically engineered for enterprise cloud workloads on Amazon Web 
Services (AWS). 

THE CORE PROBLEM IT SOLVES:
Modern cloud environments produce thousands of disparate security signals every 
day across disconnected consoles:
- AWS Security Hub provides compliance findings.
- Amazon GuardDuty detects threat intelligence anomalies and malicious IPs.
- AWS CloudTrail records raw management and data API calls.
- AWS Config tracks configuration drift and non-compliant cloud resources.
- Amazon Inspector reports software and container vulnerabilities.

In traditional security teams, human analysts suffer from acute "Alert Fatigue", 
manually cross-referencing multiple browser tabs to piece together attacks. 
By the time an analyst discovers that an API call in CloudTrail belongs to the 
same adversary running port scans detected by GuardDuty, data exfiltration has 
already occurred. Furthermore, junior analysts frequently fear running automated 
remediation because terminating an instance or revoking a credential could cause 
a severe production outage.

HOW AUTOSOC SOLVES THIS:
AutoSOC implements an autonomous 7-stage security loop:
1. DETECT: Ingests telemetry across Security Hub, GuardDuty, CloudTrail, Config, 
   and Inspector through server-side AWS SDK v3 connectors.
2. CORRELATE: A deterministic cross-plane correlation engine links isolated findings 
   sharing resources, actors, IP addresses, or VPC networks into single cohesive 
   Security Incidents.
3. TRIAGE: Evaluates real-time risk scores and calculates blast radius across 
   affected infrastructure.
4. INVESTIGATE: Integrates Amazon Bedrock (Claude 3 Sonnet) as an autonomous 
   investigation co-pilot with built-in prompt-injection defenses and secret 
   redaction, providing natural language root-cause analysis and MITRE ATT&CK 
   mapping.
5. APPROVE & RESPOND: Pre-approved automated playbooks (EC2 network isolation, 
   IAM access key deactivation, S3 public block, WAF IP reputation bans) are first 
   simulated via a Dry-Run Blast-Radius engine. High-impact remediations require 
   explicit cryptographic human-in-the-loop analyst sign-off before execution.
6. RECORD: Every action, dry-run, approval, and AWS API mutation is recorded in 
   an append-only, tamper-evident audit log with SHA-256 integrity hashing and 
   request correlation IDs.
7. REPORT: Telemetry is continuously mapped against CIS AWS Foundations Benchmark 
   v3.0, NIST CSF 2.0, and ISO/IEC 27001:2022 standards.

2. CONSOLE NAVIGATION & FEATURE BREAKDOWN (LEFT PANEL MODULES)
================================================================================

1. 🎛️ Command Center (/dashboard)
What It Does:
Acts as the central mission-control command center. It continuously polls real-time telemetry from connected AWS services, aggregates risk metrics, and presents an immediate high-level overview of the entire cloud security posture.
What Information It Gives:
- Cloud Security Risk Index (0–100 score): Real-time risk benchmark (e.g., Low Risk 8/100 or Elevated Risk 74/100) with sparkline trend graphs.
- Active Correlated Incidents: Total number of multi-signal security incidents currently requiring triage.
- Ingested Telemetry Findings: Total volume of security events captured from Security Hub, GuardDuty, CloudTrail, Config, and Inspector.
- AWS Region & Identity Pill: Live operational region (ap-south-1) and caller identity status.
- Recent Audit Activity Feed: Quick glance at the latest operator actions and dry-run simulations.

2. 🚨 Incidents & Findings (/incidents)
What It Does:
Correlates isolated telemetry across multiple AWS security tools into cohesive, prioritized security incidents. Instead of reviewing hundreds of separate logs, analysts inspect united attack timelines.
Dynamic Badge on Left Panel:
Shows an active badge: displays X Active (e.g., 2 Active) when threats exist, or green Secured when zero critical threats are open.
What Information It Gives:
- Incident & Finding Cards: Title, severity rating (CRITICAL, HIGH, MEDIUM, LOW), finding ID, and status (TRIAGE, INVESTIGATING, AWAITING_APPROVAL, REMEDIATING).
- Affected AWS Resource ARNs: Targeted EC2 instance IDs, IAM users/roles, S3 buckets, and IP addresses.
- Detection Source Tags: Identifies which AWS tools flagged the incident (GuardDuty, CloudTrail, Config, etc.).
- Filter & Search Controls: Search by resource ID, keyword, severity level, or origin service.
- Deep-Dive Workbench Link: Direct access to /incidents/[id] showing MITRE ATT&CK technique mapping.

3. ✨ AI Investigation (/investigations)
What It Does:
Provides an autonomous AI security co-pilot powered by Amazon Bedrock (Anthropic Claude 3 Sonnet). It ingests complex finding telemetry, scrubs out any sensitive AWS secrets and bearer tokens, defends against prompt injection, and generates natural-language root-cause investigations.
What Information It Gives:
- Root-Cause Analysis: Human-readable narrative detailing how the attacker gained initial access and moved laterally.
- MITRE ATT&CK Framework Mapping: Exact tactic and technique IDs (e.g., T1078: Valid Accounts, T1041: Exfiltration Over C2).
- Blast Radius Evaluation: Analysis of what databases, networks, or microservices are at risk of secondary exposure.
- Recommended Response Playbooks: Specific containment playbooks suggested by AI to neutralize the threat.

4. 🛡️ Response Playbooks (/response-playbooks) — Marked "Gated"
What It Does:
A catalog of pre-approved, safe-by-default remediation playbooks. It enforces safety by requiring a Dry-Run Blast-Radius Simulation first and requiring Analyst Cryptographic Confirmation before modifying production AWS resources.
What Information It Gives:
- Playbook Catalog:
  * EC2_QUARANTINE_ISOLATION: Moves compromised EC2 instances into a quarantine Security Group.
  * IAM_ACCESS_KEY_DEACTIVATION: Immediately invalidates compromised IAM credentials (AKIA...).
  * S3_BLOCK_PUBLIC_ACCESS: Closes publicly exposed S3 buckets.
  * WAF_IP_REPUTATION_BLOCK: Injects attacker IPs into AWS WAFv2 IP sets.
  * IAM_EXCESSIVE_PERMS_PROPOSAL: Generates least-privilege JSON policies.
- Dry-Run Blast Radius Preview: Shows the exact simulated AWS CLI command, affected dependencies (network sockets, ports, external callers), and outage risk level (HIGH, MEDIUM, LOW, ZERO).
- Approval Gate: Explains why execution is refused if prerequisites or approvals are missing.

5. 🔍 Forensics Timeline (/forensics)
What It Does:
Provides digital forensics and incident response (DFIR) analysts with an immutable, chronological timeline of management and data-plane events extracted from AWS CloudTrail.
What Information It Gives:
- Chronological Event Stream: Precise ISO UTC timestamps of all AWS API calls made during the incident.
- Actor Identity Details: Calling IAM User ARN, assumed role, or federated identity.
- Network Context: Source IPv4/IPv6 addresses and User-Agent headers.
- Cryptographic Proof: Unique SHA-256 evidence hashes for each record to preserve the legal chain of custody and prove the logs were not altered.

6. 🔑 IAM Risk Engine (/iam-risk)
What It Does:
Continuously inspects your AWS Identity and Access Management (IAM) environment to detect privilege escalation vectors, excessive wildcard permissions, and unrotated credentials.
What Information It Gives:
- Risk Findings: Flags specific IAM roles, users, and policies.
- Finding Types:
  * WILDCARD_ADMIN_POLICY (overbroad Action: "*" privileges).
  * UNUSED_PRIVILEGED_CREDS (active keys unrotated for >90 days).
  * INLINE_UNRESTRICTED_PASSROLE (risky iam:PassRole combinations).
- Affected Action Count: Quantifies how many sensitive AWS actions the identity can execute.
- JSON Policy Snippets & Remediation: Shows offending policy blocks and least-privilege GitOps replacement recommendations.

7. 📋 Compliance Mapping (/compliance)
What It Does:
Translates live AWS Config rules and telemetry into real-time compliance readiness audits against major international regulatory and security standards.
What Information It Gives:
- Supported Frameworks:
  * CIS AWS Foundations Benchmark v3.0
  * NIST CSF 2.0 (Cybersecurity Framework)
  * ISO/IEC 27001:2022
- Compliance Scoreboard: Total controls passing (PASS), failing (FAIL), or pending evaluation (NOT EVALUATED).
- Control Breakdown: Specific control IDs (e.g., CIS 1.4, CIS 2.1.1), evaluated resource IDs, rationale, and step-by-step remediation guidance.

8. 🌐 AWS Integrations (/integrations)
What It Does:
Monitors and verifies server-side connectivity, IAM operator credentials, and health states across all integrated AWS security services using live AWS STS checks.
What Information It Gives:
- Active AWS Identity: Connected Account ID, IAM Caller ARN, and AWS Region (ap-south-1).
- Per-Service Health Cards: Connection status for Security Hub, GuardDuty, CloudTrail, Config, Inspector, Bedrock, S3, DynamoDB, and KMS.
- Missing Permissions Diagnostics: Exact IAM action strings missing if an API call fails.
- AWS Cost Transparency Estimates: Transparent notes on whether each service is free, pay-per-token, or incurring API charges.
- Re-Verify Health Button: Triggers immediate STS health polling (/api/health).

9. 📜 Audit Trail (/audit-log)
What It Does:
Maintains an immutable, append-only log of every interaction inside the AutoSOC console, recording who took action, what was simulated, what was executed, and the AWS response.
What Information It Gives:
- Audit Records: Unique Event ID, UTC timestamp, actor email/role, action name, target ARN, and outcome (SUCCESS, DENIED, DRY_RUN).
- AWS Request ID & Correlation ID: Enables tracing an action in AutoSOC directly back to AWS CloudWatch or CloudTrail.
- Export Options: One-click Download CSV and Download JSON buttons for executive reporting and regulatory audits.

10. ⚙️ Settings & Flags (/settings)
What It Does:
Provides operational preferences, feature flag toggles, notification channel settings, and safeguard configurations.
What Information It Gives:
- Operational Mode Toggle: Switch between Live AWS Mode and Demo Mode ($0.00 Cost).
- Notification Controls: Enable or disable automated alerts to Slack or Email (SNS).
- Session Timeout Configuration: Set session expiry limits for analyst consoles.
- Destructive Mutation Safeguard: Displays the status of AUTOSOC_ENABLE_REMEDIATION (ensures live mutations remain blocked unless deliberately armed).

3. TANGIBLE BENEFITS & BUSINESS VALUE (WHAT THE USER GETS)
================================================================================

1. Reduction in MTTR (Mean Time to Respond) from Days to Seconds:
   Instead of manual correlation across separate AWS consoles, incidents are correlated 
   in real time and playbooks can be simulated and deployed with a single click.

2. Elimination of Alert Fatigue:
   Reduces 1,000+ isolated noisy logs into a handful of actionable, correlated security 
   incidents with prioritized risk scoring.

   Every destructive action must pass through a dry-run simulation engine that analyzes 
   affected dependencies before any live AWS API mutation occurs.

   - Zero browser secrets: AWS credentials stay strictly on the server-side runtime.
   - PII & Secret Redaction: AWS keys, passwords, and tokens are scrubbed before reaching Bedrock.

5. Instant Continuous Compliance Readiness:
   Automated real-time mapping to CIS AWS Foundations Benchmark, NIST CSF 2.0, and ISO 27001 
   eliminates weeks of manual audit evidence gathering.

6. Zero-Cost Risk-Free Evaluation:
   The built-in Demo Mode allows operators, leadership, and auditors to test every workflow 
   at $0 cloud cost without needing live AWS credentials.

6. ENVIRONMENT CONFIGURATION CONSOLIDATION (.ENV)
================================================================================

In this project, multiple environment files (such as `.env.local` vs `.env`) have been 
consolidated into ONE SINGLE GLOBAL `.env` file located at the project root.

WHY THIS WAS DONE:
Next.js naturally gives precedence to `.env.local` over `.env`. Previously, having both 
files led to configuration precedence collisions (e.g. AWS Config or Bedrock settings 
defined in `.env` were silently ignored or overridden by `.env.local`). 

CURRENT ARCHITECTURE & WIRING:
1. `c:\Users\santa\OneDrive\Desktop\AutoSOC\.env.local` has been permanently deleted.
2. `c:\Users\santa\OneDrive\Desktop\AutoSOC\.env` is the authoritative configuration 
   file for all environments:
   - Next.js development server (`npm run dev`)
   - Next.js production build (`npm run build`)
   - Local Docker container (`docker run --env-file .env`)
   - Docker Compose (`docker compose up`)
   - Production EC2 host (`./deploy-ec2.sh`)
3. The Bedrock model identifier was verified and standardized to:
   `AUTOSOC_BEDROCK_MODEL_ID=anthropic.claude-3-sonnet-20240229-v1:0`
4. The documentation (`README.md`, `src/app/docs/page.tsx`) has been wired directly 
   to reference `.env`.
